> 🎯 **Цель:** заранее подготовить внутри iiko всё, что понадобится на портале онбординга, чтобы подключение не остановилось.<br>**Для кого:** инженер iiko, подключающий ресторан · **Этап 2 из 8**.<br>**Что делается на этом этапе:** создание типов оплаты; при необходимости — создание внешнего меню и API-ключа Cloud API; внесение телефонов сотрудников для чаевых.<br>Начинайте только после этапа «1. # Перед началом

**1. Плагин Halyk Рестораны.** На кассе iiko войдите под управляющим / админом → **«Дополнения»** → найдите **«Halyk — настройка»**.

- **Пункт есть** — плагин установлен; код активации будет выдан на портале на этапе «3. Подключение — iiko».
- **Пункта нет** — обратитесь к дилеру iiko для установки, активации плагина и выдачи прав.

<details>
<summary>🔐 Права для раздела «Дополнения» (проверяет дилер iiko)</summary>

- **`F_EXT`** (Работа с внешними системами / Внешние модули) — работа с окнами внешних дополнений и API-интеграций на фронте.
- **`F_ADM`** (Администрирование кассы) — доступ к кнопке **«Дополнения» / «Инструменты»** со списком плагинов.
- **`PS_ADM`** (Администрирование плагинов) — настройка и запуск сервисных утилит плагинов.

</details>

<details>
<summary>Плагин не доступен на кассе — ручная установка (из Памятки КЦ)</summary>

1. Скопируйте папку плагина в `C:\Program Files\iiko\iikoRMS\Front.Net\Plugins\`.
2. Войдите на кассу под управляющим / админом.
3. Проверьте пункт **«Дополнения» → «Halyk — настройка»**.

> ❔ Где взять папку плагина и кто выполняет установку (дилер или инженер) — уточнить у инженера Halyk.

</details>

**2. Данные для КЦ и портала** (вносятся в **Таблицу по привлечению**):

- название ресторана, **БИН**, адрес точки, контакт ответственного;
- формат: кафе или точка на вынос (обслуживание сразу на кассе — **не подходит**);
- ERP **iiko 8.7+**, наименование и контакты дилера / техподдержки iiko;
- **CRMID** (и UID) — через кассовый терминал заведения; лицензия **HalykPayment** установлена;
- **Terminal ID** физического POS-терминала Halyk: [HALYK POS: Инструкция по получению Terminal ID](../../guides/common/halyk-pos-terminal-id.md)
- количество и нумерация столов (столы созданы в iiko, нумерация = фактической; QR-коды и схема столов подготовлены);
- Telegram-группа сотрудников (бот **@HalykRestaurantBot** — администратор), ссылка 2ГИС и логотип;
- для чаевых: у официантов карта Halyk Bank; моб. телефоны сотрудников внесены в iiko (шаг 3).

> ❔ Точный путь в интерфейсе кассы, где смотреть CRMID и UID, в источниках не описан — уточнить у инженера Halyk.

# Шаг 1. Типы оплаты

## 1.1. Тип оплаты для QR-оплаты — обязательно

Нужен для оплаты по QR на столе и на пречеке. Подробно со скриншотами: [iiko: создание оплаты для плагина Halyk Рестораны](../../guides/iiko/payment-type-plugin.md)

1. В **iikoOffice** откройте **«Администрирование» → «Настройки торгового предприятия»**.
2. Найдите заведение и его терминальную группу (в ней — отделения / секции).
3. Откройте **«Общие настройки»** и **для каждой секции** включите **«Разрешить оплату заказа без пречека»**. Сохраните.
4. Откройте **«Розничные продажи» → «Типы оплат»** и добавьте новый тип оплаты.
5. Заполните поля, **подчёркнутые на скриншоте** в детальной инструкции, — они обязательны для плагина. Остальные — по требованиям бухгалтерии заведения.
6. Сохраните тип оплаты.

> ⚠️ Если не включить **«Разрешить оплату заказа без пречека»** для каждой секции — оплата пройдёт, но чек может не закрыться в iiko.

## 1.2. Тип оплаты «HALYK самовывоз» — только если нужен самовывоз

Подробно со скриншотами: [iiko — создание типа оплаты для заказов на самовывоз Halyk Рестораны](../../guides/iiko/payment-type-pickup.md)

1. В **iikoOffice** (или **iikoChain** для сети) откройте **«Розничные продажи» → «Типы оплат»** → **«Добавить»**.
2. Заполните поля:

| Поле | Значение |
| --- | --- |
| Наименование и название на чеке | `HALYK самовывоз` |
| Код | строго `HALYK` |
| Тип | «Банковские карты» |
| «Может приниматься извне» | Включено |
| Проведение оплаты | «Как внешний, так и на стороне ресторана» |
| Остальные параметры | По скриншоту детальной инструкции и настройкам ресторана |

1. **Для iikoChain** — выберите торговые точки, где будет применяться самовывоз, и убедитесь, что тип оплаты доступен нужной точке.
2. Сохраните.

> ⚠️ **Права:** нужно **«Просматривать типы оплаты» — `B_APT`** (выдаётся в комплексе с правами администратора / менеджера бэк-офиса). Одного права просмотра может не хватить для создания и сохранения — при проблеме обратитесь к дилеру iiko. Не подменяйте этот тип оплаты типом оплаты базового QR-сценария.

# Шаг 2. Внешнее меню и API-ключ Cloud API (если нужны меню или самовывоз)

| Функции ресторана | Нужны ли внешнее меню и API-ключ |
| --- | --- |
| Базовая QR-оплата, чаевые, вызов официанта, Telegram, бронирование | **Нет** — шаг пропустите |
| **Меню** | **Да** |
| **Самовывоз** | **Да** + тип оплаты «HALYK самовывоз» (1.2) и права доставки `D_CND` / `D_ED` / `D_MD` |

**Ограничения — проверьте до начала:**

- 🚫 без прав `APP_TRANSPORT_CONFIG` / `APP_EXTERNAL_MENU` и без Cloud API в лицензии ресторана создать меню и API-ключ нельзя — обратитесь к дилеру iiko;
- номенклатура: блюдо выставлено на продажу; без блюд «можно разделить»; только **один уровень категорий**; шкалы размеров блюда и модификаторов совпадают; в артикулах нет тире и дефисов.

**Когда:** меню **Halyk QR Menu** и API-ключ создаются **сейчас, на этапе 2** — в iikoWeb по инструкции [Внешнее меню v2 и API Key](../../guides/iiko/external-menu-v2-api-key.md):

1. Доступы и права доставки — раздел «Перед началом».
2. Номенклатура — раздел 3.
3. Создание и проверка меню — раздел 4; «Выгрузить» и обновление — раздел 5.
4. Интеграция Cloud API и копирование ключа — раздел 6.
5. Вкладка «Организации»: выгрузка справочников и доступ к терминальной группе — раздел 7.

Ввод API-ключа на портале и загрузка меню — **этап 7**: [7. Внешнее меню — iiko](../07-external-menu/iiko.md).

> 🚫 **Безопасность:** API-ключ не передавайте посторонним и не публикуйте в общих чатах. Для копирования **не нажимайте «Пересоздать»** — старый ключ перестанет работать.

# Шаг 3. Телефоны сотрудников для чаевых

Внесите мобильные телефоны официантов в iiko: iikoOffice → **«Сотрудники» → «Список сотрудников»** → карточка → поле **«Моб. телефон»**. Формат и пошаговая инструкция: [iiko: добавление номера телефона сотрудника для чаевых](../../guides/iiko/tips-employee-phone.md)

> ℹ️ На этапе 8 телефоны только проверяются и включаются чаевые.

# ✅ Чек-лист «Готово к подключению»

**Общее**

- [ ] Требования этапа 1 выполнены (счёт Halyk, активный POS, MCC 5411/5441/5462/5812/5813/5814/7996/7999, обслуживание за столом, интернет, iikoFront 8.7+).
- [ ] С рестораном созвонились, чат создан, данные внесены в Таблицу по привлечению (БИН, адрес, Terminal ID, CRMID/UID, контакты дилера).
- [ ] Столы созданы в iiko, нумерация совпадает, QR-коды подготовлены.
- [ ] Telegram-группа сотрудников создана; управляющий будет на месте, функции согласованы.

**iiko — всегда**

- [ ] «Дополнения» → «Halyk — настройка» доступно; права F\_EXT / F\_ADM / PS\_ADM есть; лицензия HalykPayment установлена.
- [ ] Тип оплаты для QR создан; «Разрешить оплату заказа без пречека» включено во всех секциях.
- [ ] Телефоны сотрудников для чаевых внесены в iiko (шаг 3).

**iiko — если нужны меню или самовывоз**

- [ ] Права `APP_TRANSPORT_CONFIG`, `APP_EXTERNAL_MENU`; Cloud API в лицензии.
- [ ] Номенклатура соответствует требованиям; меню **Halyk QR Menu** создано, наполнено, сохранено и выгружено.
- [ ] Интеграция Cloud API настроена — чек-лист 6.5 инструкции пройден.
- [ ] «Организации»: выгрузка справочников и галочка «Данные» у терминальной группы.
- [ ] API-ключ скопирован и хранится безопасно (не опубликован).

**iiko — если нужен самовывоз**

- [ ] Тип оплаты «HALYK самовывоз» (код `HALYK`, «Банковские карты», «Может приниматься извне») создан; для iikoChain — точки выбраны.
- [ ] Права доставки D\_CND / D\_ED / D\_MD выданы кассиру.

> ✅ Все пункты отмечены — можно переходить к этапу «3. Подключение — iiko».

> ℹ️ Ввод API-ключа на портале и загрузка меню — этап [«7. Внешнее меню — iiko»](../07-external-menu/iiko.md).
