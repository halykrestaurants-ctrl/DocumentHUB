# 2. Подготовка к подключению — iiko

> 🎯 **Цель:** заранее подготовить внутри iiko всё, что понадобится на портале онбординга, чтобы подключение не остановилось.<br>**Для кого:** инженер iiko, подключающий ресторан · **Этап 2 из 8**.<br>**Что делается на этом этапе:** создание типов оплаты; при необходимости — создание внешнего меню; для меню / самовывоза — создание и настройка API-ключа Cloud API.<br>Начинайте только после этапа «1. Требования — iiko». Ввод API-ключа на портале и загрузка меню — **этап 7**, не здесь.

---

# Перед началом

**1. Плагин Halyk Рестораны.** На кассе iiko войдите под управляющим / админом → **«Дополнения»** → найдите **«Halyk — настройка»**.

- **Пункт есть** — плагин установлен; код активации будет выдан на портале на этапе «3. Подключение — iiko».
- **Пункта нет** — обратитесь к дилеру iiko для установки, активации плагина и выдачи прав.

<details>
<summary>🔐 Права для раздела «Дополнения» (проверяет дилер iiko)</summary>

- **`F_EXT`** (Работа с внешними системами / Внешние модули) — работа с окнами внешних дополнений и API-интеграций на фронте.
- **`F_ADM`** (Администрирование кассы) — доступ к кнопке **«Дополнения» / «Инструменты»** со списком плагинов.
- **`PS_ADM`** (Администрирование плагинов) — настройка и запуск сервисных утилит плагинов.

</details>

<details>
<summary>Плагин не доступен на кассе — ручная установка (из Памятки КЦ)</summary>

1. Скопируйте папку плагина в `C:\Program Files\iiko\iikoRMS\Front.Net\Plugins\`.
2. Войдите на кассу под управляющим / админом.
3. Проверьте пункт **«Дополнения» → «Halyk — настройка»**.

> ❔ Где взять папку плагина и кто выполняет установку (дилер или инженер) — уточнить у инженера Halyk.

</details>

**2. Данные для КЦ и портала** (вносятся в **Таблицу по привлечению**):

- название ресторана, **БИН**, адрес точки, контакт ответственного;
- формат: кафе или точка на вынос (обслуживание сразу на кассе — **не подходит**);
- ERP **iiko 8.7+**, наименование и контакты дилера / техподдержки iiko;
- **CRMID** (и UID) — через кассовый терминал заведения; лицензия **HalykPayment** установлена;
- **Terminal ID** физического POS-терминала Halyk: [HALYK POS: Инструкция по получению Terminal ID](../../guides/common/halyk-pos-terminal-id.md)
- количество и нумерация столов (столы созданы в iiko, нумерация = фактической; QR-коды и схема столов подготовлены);
- Telegram-группа сотрудников (бот **@HalykRestaurantBot** — администратор), ссылка 2ГИС и логотип;
- для чаевых: у официантов карта Halyk Bank, моб. телефон в iiko в формате `7XXXXXXXXXX` / `8XXXXXXXXXX` (11 цифр, без «+», пробелов, скобок, дефисов): [iiko: добавление номера телефона сотрудника для чаевых](../../guides/iiko/tips-employee-phone.md)

> ❔ Точный путь в интерфейсе кассы, где смотреть CRMID и UID, в источниках не описан — уточнить у инженера Halyk.

# Шаг 1. Типы оплаты

## 1.1. Тип оплаты для QR-оплаты — обязательно

Нужен для оплаты по QR на столе и на пречеке. Подробно со скриншотами: [iiko: создание оплаты для плагина Halyk Рестораны](../../guides/iiko/payment-type-plugin.md)

1. В **iikoOffice** откройте **«Администрирование» → «Настройки торгового предприятия»**.
2. Найдите заведение и его терминальную группу (в ней — отделения / секции).
3. Откройте **«Общие настройки»** и **для каждой секции** включите **«Разрешить оплату заказа без пречека»**. Сохраните.
4. Откройте **«Розничные продажи» → «Типы оплат»** и добавьте новый тип оплаты.
5. Заполните поля, **подчёркнутые на скриншоте** в детальной инструкции, — они обязательны для плагина. Остальные — по требованиям бухгалтерии заведения.
6. Сохраните тип оплаты.

> ⚠️ Если не включить **«Разрешить оплату заказа без пречека»** для каждой секции — оплата пройдёт, но чек может не закрыться в iiko.

## 1.2. Тип оплаты «HALYK самовывоз» — только если нужен самовывоз

Подробно со скриншотами: [iiko — создание типа оплаты для заказов на самовывоз Halyk Рестораны](../../guides/iiko/payment-type-pickup.md)

1. В **iikoOffice** (или **iikoChain** для сети) откройте **«Розничные продажи» → «Типы оплат»** → **«Добавить»**.
2. Заполните поля:

| Поле | Значение |
| --- | --- |
| Наименование и название на чеке | `HALYK самовывоз` |
| Код | строго `HALYK` |
| Тип | «Банковские карты» |
| «Может приниматься извне» | Включено |
| Проведение оплаты | «Как внешний, так и на стороне ресторана» |
| Остальные параметры | По скриншоту детальной инструкции и настройкам ресторана |

1. **Для iikoChain** — выберите торговые точки, где будет применяться самовывоз, и убедитесь, что тип оплаты доступен нужной точке.
2. Сохраните.

> ⚠️ **Права:** нужно **«Просматривать типы оплаты» — `B_APT`** (выдаётся в комплексе с правами администратора / менеджера бэк-офиса). Одного права просмотра может не хватить для создания и сохранения — при проблеме обратитесь к дилеру iiko. Не подменяйте этот тип оплаты типом оплаты базового QR-сценария.

# Шаг 2. Внешнее меню (если нужны меню или самовывоз)

> ℹ️ **Для базовой QR-оплаты, чаевых, вызова официанта, Telegram, бронирования внешнее меню и API-ключ не нужны** — пропустите шаги 2 и 3. Для **«Меню»** нужны шаги 2 и 3; для **«Самовывоза»** — шаги 2, 3 и тип оплаты «HALYK самовывоз» (1.2) + права доставки.

## 2.1. Проверьте доступы

- **iikoOffice / iikoChain** — вход в систему нужного ресторана и доступ к **«Отчеты → Отчеты iikoWeb»**.
- **iikoWeb** — доступ к приложениям **«Настройки Cloud API»** (`APP_TRANSPORT_CONFIG`) и **«Внешние меню»** (`APP_EXTERNAL_MENU`).
- **Cloud API** — уточните у дилера, что сервис входит в **лицензию** ресторана.

> 🚫 Без прав `APP_TRANSPORT_CONFIG` / `APP_EXTERNAL_MENU` и без Cloud API в лицензии создать меню и API-ключ нельзя — обратитесь к дилеру iiko.

## 2.2. Проверьте номенклатуру

- блюдо **выставлено на продажу** — указаны цена и места продаж;
- **не поддерживаются блюда, которые можно делить пополам** (опция **«Блюдо можно разделить»** в схеме модификаторов);
- только **один уровень категорий** — вложенные подкатегории не создаются;
- **шкалы размеров** блюда и его модификаторов должны совпадать (у блюда S, M, L, у модификатора только S, M — модификатор не выгрузится);
- в **артикулах** не должно быть тире и дефисов — такие блюда не передаются.

## 2.3. Создайте меню «Halyk QR Menu» в iikoWeb

1. В iikoOffice / iikoChain откройте **«Отчеты → Отчеты iikoWeb»** и авторизуйтесь (обычно логин и пароль iikoOffice; если не подходят — уточните у администратора или дилера).
2. На главной странице в блоке **«Внешние заказы»** выберите **«Внешние меню»** → **«Добавить»**.
3. Заполните форму:

| Поле | Значение |
| --- | --- |
| **«Наименование»** | **Halyk QR Menu** |
| **«Ресторан для загрузки цен»** | Подключаемый ресторан |
| **«Источник цен»** | Прайс-лист ресторана (например, «Базовый прайс-лист») |
| Описание | По необходимости |

1. Выберите способ создания и нажмите **«Сохранить»**:
   - **вручную** — полный контроль состава и вида; для меню со структурой, отличной от номенклатуры;
   - **автоматически («Сгенерировать меню»)** — попадут все блюда с ценой и местом продажи; картинки, названия и описания берутся из карточек блюд. Вложенные папки станут отдельными категориями (например, «Мороженое» и «Торты» внутри «Десерты» — две категории).

> ⚠️ В разных инструкциях встречается и `HALYK QR Menu`; чувствительность к регистру не подтверждена. Если меню уже существует — выберите его, не создавайте дубль из-за регистра. Если портал не находит меню — сверьте написание с инженером Halyk.

## 2.4. Проверьте меню

1. Откройте меню → вкладка **«Список блюд»** → при необходимости включите **«Редактирование»**.
2. Проверьте категории, блюда, цены, изображения, размеры и модификаторы. При ручном создании добавьте категории и блюда — **пустое меню к подключению не готово**.
3. После правок нажмите **«Сохранить»**.

<details>
<summary>Что можно отредактировать в сгенерированном меню</summary>

- порядок позиций внутри группы и порядок групп — кнопкой перемещения (перетаскиванием);
- удалить группу — иконка редактирования в строке группы → **«Удалить группу»**;
- расписание категории — иконка редактирования → поле **«Расписание»**;
- цену блюда — карточка блюда на вкладке «Список блюд» → блок **«Детали»** (цена действует только в этом внешнем меню).

</details>

## 2.5. Обновление меню

> ⚠️ **Внешнее меню не синхронизируется с номенклатурой автоматически** — после изменений блюд и цен обновляйте его вручную. Автоматически обновляются только **модификаторы** (изменения сразу применяются во всех внешних меню).

- **Всё меню:** кнопка обновления данных → отметьте поля для синхронизации (проверьте галочку **«Цены»**, чтобы не перезаписать цены, заданные вручную) → **«Обновить»**.
- **Одно блюдо:** карточка блюда → кнопка обновления → подтвердить → проверить результат. Описание блюда так **не обновляется** — для него обновите всё меню с полем **«Названия и описания блюд»**.
- **Чтобы изменения дошли до Halyk:** ресторан нажимает **«Выгрузить»** после финализации меню; ускорить синхронизацию — на кассе в правом нижнем углу **«Дополнения» → «Синхронизировать меню»**; затем проверьте меню на стороне Halyk Рестораны.

# Шаг 3. API-ключ Cloud API (если нужны меню или самовывоз)

## 3.1. Создайте интеграцию

1. В iikoWeb откройте **«Внешние заказы → Настройки Cloud API»**.
2. Вкладка **«Интеграции»** → **«Добавить интеграцию»** — откроется карточка API-логина.
3. Вкладка **«Подключенные точки»** → **«Добавить точку»** → отметьте нужное заведение → **«Добавить»**. Проверьте, что ресторан (именно текущий) появился в списке.
4. Вкладка **«Основное»** — заполните поля:

| Поле | Значение |
| --- | --- |
| **«Имя API логина»** | `Halyk рестораны-самовывоз` |
| **Email** | Действующий адрес ответственного за интеграцию (уведомления Cloud API) |
| **«Шаблон прав»** | **«Все права»** (широкие права; возможность более узкого шаблона — на проверке у владельца интеграции) |
| **«Источник заказа»** | `Halyk Рестораны` — не заменять произвольным названием: источник ограничивает видимость заказов через API |
| **«Внешнее меню»** | **Halyk QR Menu** текущего ресторана (отмечено в списке) |
| **«Источник цен»** | **«Внешнее меню»** |
| **«Интеграция активна»** | Включено |
| Срок действия API-ключа | От 2 дней до **2 лет** (по умолчанию — 2 года); укажите актуальную дату, не со скриншота |

1. Нажмите **«Сохранить»** после заполнения всех полей, включая имя API-логина.

> ⚠️ **Не путайте два поля «Источник цен».** В самом меню — прайс-лист ресторана, в карточке API — **«Внешнее меню»**.

## 3.2. Вкладка «Организации»: выгрузка данных

Добавить точку в интеграцию и открыть доступ к терминальной группе — **разные действия**, нужны оба.

1. Выйдите из карточки API-логина стрелкой назад.
2. Откройте вкладку **«Организации»** → нажмите на название нужного ресторана.
3. На вкладке **«Основное»**:
   - включите **«Разрешить выгрузку справочников в Cloud API»**;
   - в разделе **«Разрешить доступ к терминальным группам»** поставьте галочку в столбце **«Данные»** у нужной терминальной группы.
4. Нажмите **«Сохранить»**.

> ⚠️ Для самовывоза отмечайте группу той кассы, которая будет принимать заказы. Если сервер или касса недоступны в списке организаций — обратитесь к дилеру iiko.

## 3.3. Скопируйте API-ключ

Скопируйте ключ **кнопкой** рядом с полем **«API ключ»** (звёздочки на экране скрывают значение). Сохраните его для этапа 7 или передайте ответственному сервисанту Halyk Банка по согласованному рабочему каналу.

> 🚫 **Безопасность:** API-ключ не передавайте посторонним и не публикуйте в общих чатах и инструкциях. Для копирования **не нажимайте «Пересоздать»** — старый ключ перестанет работать.

## 3.4. Права доставки — только для самовывоза

Права сотруднику на кассе выдаёт техподдержка дилера; раздел на кассе: **дополнительное меню iikoFront → Сервис → Доставка**.

| Право | Назначение |
| --- | --- |
| `D_CND` | Подтверждать доставки |
| `D_ED` | Редактирование доставки |
| `D_MD` | Управление доставкой |

> 📸 Подробная инструкция со скриншотами (создание меню, интеграция Cloud API, вкладка «Организации»): [Внешнее меню v2 и API Key](../../guides/iiko/external-menu-v2-api-key.md)

# ✅ Чек-лист «Готово к подключению»

**Общее**

- [ ] Требования этапа 1 выполнены (счёт Halyk, активный POS, MCC 5812/5813/5814, обслуживание за столом, интернет, iikoFront 8.7+).
- [ ] С рестораном созвонились, чат создан, данные внесены в Таблицу по привлечению (БИН, адрес, Terminal ID, CRMID/UID, контакты дилера).
- [ ] Столы созданы в iiko, нумерация совпадает, QR-коды подготовлены; телефоны сотрудников для чаевых заполнены.
- [ ] Telegram-группа сотрудников создана; управляющий будет на месте, функции согласованы.

**iiko — всегда**

- [ ] «Дополнения» → «Halyk — настройка» доступно; права F\_EXT / F\_ADM / PS\_ADM есть; лицензия HalykPayment установлена.
- [ ] Тип оплаты для QR создан; «Разрешить оплату заказа без пречека» включено во всех секциях.

**iiko — если нужны меню или самовывоз**

- [ ] Права `APP_TRANSPORT_CONFIG`, `APP_EXTERNAL_MENU`; Cloud API в лицензии.
- [ ] Номенклатура соответствует требованиям; меню **Halyk QR Menu** создано, наполнено, сохранено и выгружено.
- [ ] Интеграция Cloud API: точка, имя логина, Email, «Все права», источник заказа «Halyk Рестораны», меню, источник цен «Внешнее меню», активна, срок ключа.
- [ ] «Организации»: выгрузка справочников и галочка «Данные» у терминальной группы.
- [ ] API-ключ скопирован и хранится безопасно (не опубликован).

**iiko — если нужен самовывоз**

- [ ] Тип оплаты «HALYK самовывоз» (код `HALYK`, «Банковские карты», «Может приниматься извне») создан; для iikoChain — точки выбраны.
- [ ] Права доставки D\_CND / D\_ED / D\_MD выданы кассиру.

> ✅ Все пункты отмечены — можно переходить к этапу «3. Подключение — iiko».

> ℹ️ Ввод API-ключа на портале и загрузка меню — этап «7. Внешнее меню — iiko».
