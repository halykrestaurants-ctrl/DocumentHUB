# 2. Подготовка к подключению

> 🎯 <b>Цель:</b> собрать все данные и заранее настроить кассу, чтобы на портале онбординга ничего не остановило подключение.<br /><b>Для кого:</b> КЦ, сервисант, инженер / привлеченец, сотрудник ресторана.<br /><b>Этап 2 из 8.</b> Начинайте только после этапа «1. Требования к подключению».<br /><b>Следующий шаг:</b> «3. Подключение» (портал онбординга).

# Для всех ERP

## Данные, которые собирает КЦ

КЦ получает от ресторана и вносит в <b>Таблицу по привлечению</b>:

- [ ] название ресторана;
- [ ] БИН;
- [ ] формат: кафе или точка на вынос (если обслуживание сразу на кассе — <b>не подходит</b>);
- [ ] ERP-система и её версия: <b>iiko 8.7+</b>, <b>r\_keeper 7.7.0.390+</b>, <b>ROSTA 1.13.9+</b>;
- [ ] наименование и контакты компании техподдержки (дилера) iiko / r\_keeper;
- [ ] r\_keeper: <b>ObjectId (код ресторана)</b>;
- [ ] iiko: <b>CRMID</b>;
- [ ] адрес точки;
- [ ] контакт ответственного.

## Что сервисант делает перед выездом

1. Созванивается с рестораном и подтверждает готовность к подключению.
2. Создаёт чат и собирает данные.
3. Получает от Halyk Lifestyle / заведения данные по своей ERP (см. таблицу ниже).

| ERP | Что получить до выезда |
|---|---|
| <b>iiko</b> | наименование и контакты техподдержки; CRMID; UID; лицензия HalykPayment установлена; тип оплаты Halyk Рестораны создан; API-Key (только для меню / самовывоза); количество и нумерация столов |
| <b>r\_keeper</b> | наименование и контакты техподдержки; ObjectId (код ресторана); количество и нумерация столов; лицензия выдана; GUID валюты получен |
| <b>Poster</b> | доступ к аккаунту (email и пароль); тариф (для меню); нумерация столов |
| <b>Paloma365</b> | доступ к настройкам кассы (пароль); доступ к веб-интерфейсу (для меню); нумерация столов |
| <b>ROSTA</b> | версия ПО <b>1.13.9 или выше</b>; доступ владельца к <b>ROSTA Mobile Office</b>; торговая точка, касса и меню; настроенный способ оплаты Halyk; доступ к приложению Halyk для OTP-кода |

## Данные для портала (все ERP)

- [ ] <b>БИН</b> организации, <b>адрес</b> точки и соответствующий <b>ID терминала</b>.
- [ ] <b>Terminal ID</b> физического POS-терминала Halyk, которым ресторан фактически принимает оплаты: [HALYK POS: Инструкция по получению Terminal ID](../guides/common/halyk-pos-terminal-id.md)
- [ ] Столы созданы в ERP; нумерация в ERP = фактическая нумерация; подготовлены физические QR-коды и схема столов (для режима «По столам»).
- [ ] Telegram-группа сотрудников и возможность добавить бота <b>@HalykRestaurantBot</b> администратором.
- [ ] Данные для карточки ресторана: ссылка 2ГИС (без пробелов и лишних символов), логотип при наличии; управляющий готов проверить карточку и выбрать функции.
- [ ] Для чаевых: у официантов есть карта Halyk Bank, телефоны сотрудников будут заполнены в ERP.

# iiko

## 1. Проверьте плагин Halyk Рестораны

1. На кассе iiko войдите под пользователем с доступом к разделу <b>«Дополнения»</b> (управляющий / админ).
2. Откройте <b>«Дополнения»</b>.
3. Найдите пункт <b>«Halyk — настройка»</b>.

- <b>Пункт есть</b> — плагин установлен. Код активации вы получите на портале на этапе «3. Подключение».
- <b>Пункта нет</b> — обратитесь к дилеру iiko для установки, активации плагина и выдачи прав.

<details>
<summary>🔐 Какие права нужны для раздела «Дополнения»</summary>

- <b><code>F_EXT</code></b> (Работа с внешними системами / Внешние модули) — запуск и работа с окнами внешних дополнений и API-интеграций на фронте.
- <b><code>F_ADM</code></b> (Администрирование кассы) — доступ к кнопке <b>«Дополнения» / «Инструменты»</b>, где находится список установленных плагинов.
- <b><code>PS_ADM</code></b> (Администрирование плагинов) — настройка и запуск сервисных утилит плагинов.

Доступ выдаёт сотрудник с нужными полномочиями в iiko. Права должен проверить дилер iiko.

</details>

<details>
<summary>Плагин не доступен на кассе — ручная установка (из Памятки КЦ)</summary>

1. Скопируйте папку плагина в <code>C:\Program Files\iiko\iikoRMS\Front.Net\Plugins\</code>.
2. На кассе войдите под пользователем с правами (управляющий / админ).
3. Проверьте, что появился пункт <b>«Дополнения» → «Halyk — настройка»</b>.

> ❔ Где взять папку плагина и кто выполняет установку (дилер или инженер) — уточнить у инженера Halyk.

</details>

## 2. Получите CRMID

Получите <b>CRMID</b> через кассовый терминал заведения и внесите в Таблицу по привлечению. Также уточните компанию техподдержки (дилера) iiko.

> ❔ Точный путь в интерфейсе кассы, где смотреть CRMID и UID, в источниках не описан. Уточнить у инженера Halyk.

## 3. Создайте тип оплаты для QR-оплаты (обязательно)

Нужен для оплаты по QR на столе и на пречеке. Подробно со скриншотами: [iiko: создание оплаты для плагина Halyk Рестораны](../guides/iiko/payment-type-plugin.md)

1. В <b>iikoOffice</b> откройте <b>«Администрирование» → «Настройки торгового предприятия»</b>.
2. Найдите заведение и его терминальную группу (в ней — отделения / секции).
3. Откройте <b>«Общие настройки»</b> и <b>для каждой секции</b> включите <b>«Разрешить оплату заказа без пречека»</b>. Сохраните.
4. Откройте <b>«Розничные продажи» → «Типы оплат»</b> и добавьте новый тип оплаты.
5. Заполните <b>подчёркнутые на скриншоте</b> поля — они обязательны для плагина. Остальные поля — по требованиям бухгалтерии заведения.
6. Сохраните тип оплаты.

> ⚠️ Если не включить <b>«Разрешить оплату заказа без пречека»</b> для каждой секции — оплата пройдёт, но чек может не закрыться в iiko.

## 4. Тип оплаты «HALYK самовывоз» — только если нужен самовывоз

Подробно со скриншотами: [iiko — создание типа оплаты для заказов на самовывоз Halyk Рестораны](../guides/iiko/payment-type-pickup.md)

1. В <b>iikoOffice</b> (или <b>iikoChain</b> для сети) откройте <b>«Розничные продажи» → «Типы оплат»</b>. Нужно право <b>«Просматривать типы оплаты» — </b><b><code>B_APT</code></b> (выдаётся в комплексе с правами администратора или менеджера бэк-офиса; проверяет дилер).
2. Создайте тип оплаты с названием <b>«HALYK самовывоз»</b> и кодом строго <b><code>HALYK</code></b>.
3. Для <b>iikoChain</b> — укажите торговые точки, в которых будет использоваться самовывоз.
4. Сохраните.
5. Попросите дилера выдать кассиру права на доставку: <b><code>D_CND</code></b> (подтверждать), <b><code>D_ED</code></b> (редактировать), <b><code>D_MD</code></b> (управлять).

## 5. API-ключ — только для меню и самовывоза

> ⚠️ <b>Для базовой QR-оплаты API-ключ не требуется.</b> Если нужны меню или самовывоз — заранее создайте внешнее меню <b>Halyk QR Menu</b> и API-ключ по инструкции [Внешнее меню v2 и API Key](../guides/iiko/external-menu-v2-api-key.md). Нужны права в iikoOffice / iikoChain, iikoWeb, Cloud API и в разделе внешних меню; Cloud API должен входить в лицензию ресторана. API-ключ нельзя передавать посторонним и публиковать в общих чатах.

## 6. Столы и телефоны сотрудников

- [ ] Столы созданы в iiko (иначе они не появятся на портале).
- [ ] Для чаевых у сотрудников в iiko заполнен моб. телефон в формате <code>7XXXXXXXXXX</code> или <code>8XXXXXXXXXX</code> (11 цифр, без «+», пробелов, скобок и дефисов): [iiko: добавление номера телефона сотрудника для чаевых](../guides/iiko/tips-employee-phone.md)

> ✅ Готово, если: пункт <b>«Halyk — настройка»</b> доступен, CRMID получен, тип оплаты для QR создан и активен, «Разрешить оплату заказа без пречека» включено во всех секциях; при самовывозе — созданы «HALYK самовывоз», меню Halyk QR Menu и API-ключ.

# r\_keeper

> 🚫 <b>Подключение r\_keeper к Halyk Рестораны выполняется только после выдачи лицензии и получения GUID валюты.</b> Пока не выполнены оба условия, на портал не идём.

## 1. Определите обслуживающего дилера

Это компания, которая внедряла r\_keeper, оказывает техподдержку, продлевает лицензии и обслуживает оборудование. Где найти контакты:

- в договоре сопровождения;
- на кассе в разделе <b>«Инфо о дилере»</b>;
- запросить у технической поддержки r\_keeper.

## 2. Соберите данные для дилера и портала

- [ ] <b>Код ресторана (ObjectId)</b> r\_keeper (вводится на портале; если неизвестен — уточнить у дилера).
- [ ] Номер лицензии r\_keeper.
- [ ] Название организации и ресторана, <b>БИН</b>, адрес точки.
- [ ] Количество кассовых станций.
- [ ] Версия Windows и версия кассового сервера r\_keeper.
- [ ] Обслуживающий дилер и его контакты.
- [ ] ФИО и мобильный номер представителя заведения.
- [ ] Terminal ID активного POS-терминала Halyk.

## 3. Направьте заявку дилеру

Шаблон письма дилеру:

> Добрый день.<br />Наше заведение работает на системе r\_keeper «код ресторана».<br />Просим предоставить коммерческое предложение на подключение сервиса «Halyk Рестораны» и оформить необходимые лицензии r\_keeper по подписке для интеграции с сервисом «Halyk Рестораны».<br />Просим сообщить стоимость лицензий, сроки подключения и перечень необходимых работ.

Подробная инструкция для клиента: [Самостоятельное приобретение лицензии rkeeper](../guides/r_keeper/license-purchase.md)

## 4. Лицензия по подписке

1. Дилер проверяет текущую конфигурацию r\_keeper и определяет необходимые лицензии и модули.
2. Готовит коммерческое предложение и выставляет счёт на лицензии и работы по настройке (подписка — ежемесячная или годовая).
3. Ресторан подписывает договор (если требуется), оплачивает счёт и передаёт подтверждение оплаты дилеру.
4. Дилер регистрирует лицензии в системе лицензирования r\_keeper и настраивает интеграцию.

## 5. Валюта Halyk QR и GUID валюты

1. Дилер создаёт в r\_keeper валюту <b>Halyk QR</b> — после интеграции заказ закрывается как <b>HALYK QR</b>.
2. Получите <b>GUID валюты</b> до начала подключения.

> ❔ Куда и кому передаётся GUID валюты и какие именно настройки валюты делает дилер, в источниках не описано. Уточнить у инженера Halyk.

<details>
<summary>Если потом оплата пройдёт, а чек не закроется</summary>

Причина — настройки валюты в r\_keeper. Привлеките обслуживающего дилера; после исправления повторите тестовую оплату.

</details>

## 6. Столы и телефоны сотрудников

- [ ] Количество и нумерация столов в r\_keeper совпадают с физическими.
- [ ] Для чаевых: в менеджерской станции <b>«Персонал» → «Работники»</b> у сотрудников заполнено поле <b>«Телефон»</b> (системное имя <b>PhoneNumber</b>): [RKEEPER: добавление номера телефона сотрудника для чаевых](../guides/r_keeper/tips-employee-phone.md)

> ⚠️ Для r\_keeper <b>API-ключ не нужен</b> — на портале этот шаг пропускается.

> ✅ Готово, если: лицензия выдана, валюта Halyk QR создана, GUID валюты получен, интеграция для нужного ресторана подготовлена с дилером, код ресторана (ObjectId) известен.

# Poster

## 1. Доступ к аккаунту

- [ ] Ответственный сотрудник с доступом в аккаунт Poster нужного ресторана будет на месте.
- [ ] Известны <b>email и пароль</b> аккаунта Poster (вводятся при интеграции на портале).
- [ ] Известно, какая <b>организация</b> и какое <b>меню</b> в аккаунте относятся к подключаемой точке.

## 2. Тариф и внешнее меню (если нужны меню / самовывоз)

> ⚠️ Для внешнего меню Poster требуется тариф <b>PRO или BUSINESS</b>. Если меню нужно уже на этапе выбора в портале — подготовьте его заранее.

1. Откройте <b>«Настройки» → «Заказы»</b> → <b>«Создать источник заказа»</b>, название, например, <b>Halyk Restaurants</b>; флажок <b>«Отображать на кассе»</b>; <b>«Сохранить»</b>.
2. Откройте <b>«Меню» → «Товары»</b> — по умолчанию все товары уже привязаны к созданному источнику. Только у блюд, которых не должно быть во внешнем меню, в карточке (<b>«Источники заказов»</b>) снимите галочку и сохраните; проверьте категории и цены.

Подробно со скриншотами: [Внешнее меню POSTER](../guides/poster/external-menu.md)

## 3. Столы и телефоны сотрудников

- [ ] Столы в Poster совпадают с физическими.
- [ ] Для чаевых: в личном кабинете Poster <b>«Доступ» → «Сотрудники»</b> заполнены номера телефонов: [POSTER: добавление номера телефона сотрудника для чаевых](../guides/poster/tips-employee-phone.md)

> ❔ Прочие настройки для удалённого заказа в Poster в источниках не описаны. Уточнить у инженера Halyk.

> ✅ Готово, если: есть email и пароль аккаунта Poster нужного ресторана; для меню — тариф PRO / BUSINESS, источник заказа создан, галочка снята только у блюд, которых не должно быть во внешнем меню.

# Paloma365

## 1. Обновите ПО до актуальной версии

1. На кассе откройте <b>«МЕНЮ» → «Настройки»</b>, введите пароль <code>00000</code> (пароль может быть изменён).
2. Перейдите во вкладку <b>«Настройки аккаунта»</b>.
3. Нажмите <b>«Обновить программу»</b>.

## 2. Включите плагин

1. После обновления откройте <b>«Меню» → «Настройки» → «Плагины»</b>.
2. Включите <b>«Использовать Halyk Рестораны»</b>.
3. В окне плагина есть поле для <b>кода подключения</b> — код вы получите на портале на этапе «3. Подключение» (на портале для Paloma365 выбирается ERP <b>Universal API</b>).

## 3. Выберите вид оплаты

В настройках плагина выберите или создайте <b>вид оплаты</b> для Halyk Рестораны.

> ⚠️ <b>Не выбирайте вид оплаты «картой».</b>

## 4. Доставка и меню (если нужны)

- Для работы с доставкой в окне плагина необходимо включить соответствующие настройки.
- Меню готовится в <b>веб-интерфейсе Paloma365</b> → <b>«Меню»</b> («Добавить» или «Изменить»; название, тип цены), затем выбирается на кассе в окне плагина.

> ⚠️ Обязательное условие для меню: <b>1 уровень меню, не больше</b>.

> ❔ Какие именно настройки доставки включать в плагине (в источнике — только скриншот) — уточнить у инженера Halyk.

> ✅ Готово, если: ПО обновлено, «Использовать Halyk Рестораны» включено, вид оплаты выбран (не «картой»).

# ROSTA

> ℹ️ Для ROSTA подключение выполняется самостоятельно владельцем через <b>ROSTA Mobile Office</b>. На этапе подготовки убедитесь, что всё ниже готово.

## 1. Версия ПО

- [ ] Версия ROSTA на объекте — <b>не ниже 1.13.9</b>. Если ниже — обновите до актуальной.

## 2. Способ оплаты «Halyk»

- [ ] В ROSTA создан и настроен способ оплаты <b>«Halyk»</b> с типом <b>«Безналичный»</b>.

## 3. Доступы

- [ ] У владельца есть доступ к <b>ROSTA Mobile Office</b>.
- [ ] Есть доступ к <b>приложению Halyk</b>, из которого берётся <b>OTP-код</b> для безопасного подключения интеграции.

## 4. Данные для подключения

- [ ] Определены <b>торговая точка</b>, <b>касса</b> и <b>меню</b> для интеграции и проверены их настройки в ROSTA.

<details>
<summary>Частые вопросы</summary>

- <b>Интеграция «Halyk рестораны» не отображается</b> — сначала проверьте версию ROSTA (нужна 1.13.9+).
- <b>Нужного способа оплаты нет</b> — создайте или настройте способ оплаты Halyk в ROSTA.
- <b>Не отображается торговая точка, касса или меню</b> — проверьте их настройки в ROSTA до запуска интеграции.

</details>

Официальная инструкция ROSTA: [Инструкция по самостоятельной интеграции](https://academy.rosta.kz/?article=f45ca3e3-be09-4144-903e-1794ea994002)

> ✅ Готово, если: версия 1.13.9+, способ оплаты «Halyk» (безналичный) создан, владелец имеет доступ к ROSTA Mobile Office и приложению Halyk.
